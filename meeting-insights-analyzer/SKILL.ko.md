# 회의 인사이트 분석기

이 스킬은 회의 녹취록을 커뮤니케이션 패턴에 대한 실행 가능한 인사이트로 변환하여 더 효과적인 커뮤니케이터이자 리더가 될 수 있도록 도와줍니다.

## 이 스킬을 사용해야 하는 경우

- 여러 회의에 걸친 커뮤니케이션 패턴 분석
- 리더십 및 진행 스타일에 대한 피드백 받기
- 어려운 대화를 피하는 경우 파악
- 말하기 습관과 군더더기 말 이해하기
- 시간 경과에 따른 커뮤니케이션 스킬 개선 추적
- 구체적인 예시를 통한 성과 평가 준비
- 팀원의 커뮤니케이션 스타일 코칭

## 이 스킬이 하는 일

1. **패턴 인식**: 다음과 같은 회의 간 반복되는 행동 파악:
   - 갈등 회피 또는 간접적 커뮤니케이션
   - 발언 비율 및 차례 주고받기
   - 질문하기 대 진술하기 패턴
   - 적극적 경청 지표
   - 의사결정 접근 방식

2. **커뮤니케이션 분석**: 커뮤니케이션 효과성 평가:
   - 명확성과 직접성
   - 군더더기 말과 회피 언어 사용
   - 어조와 감정 패턴
   - 회의 제어 및 진행

3. **실행 가능한 피드백**: 다음 내용이 포함된 구체적이고 타임스탬프가 있는 예시 제공:
   - 무슨 일이 일어났는지
   - 왜 중요한지
   - 어떻게 개선할 수 있는지

4. **추세 추적**: 여러 회의를 분석할 때 시간 경과에 따른 패턴 비교

## 사용 방법

### 기본 설정

1. 회의 녹취록을 폴더(예: `~/meetings/`)에 다운로드
2. Claude Code에서 해당 폴더로 이동
3. 원하는 분석 요청

### 빠른 시작 예시

```
이 폴더의 모든 회의를 분석하고 내가 갈등을 회피한 경우를 알려주세요.
```

```
지난 달 회의를 살펴보고 내 커뮤니케이션 패턴을 파악해주세요.
```

```
이 두 회의 폴더 간의 내 진행 스타일을 비교해주세요.
```

### 고급 분석

```
이 폴더의 모든 녹취록을 분석하고:
1. 내가 다른 사람을 방해한 경우 파악
2. 내 발언 비율 계산
3. 직접적인 피드백을 회피한 순간 찾기
4. 군더더기 말 사용 추적
5. 좋은 적극적 경청의 예시 보여주기
```

## 지침

사용자가 회의 분석을 요청할 때:

1. **사용 가능한 데이터 발견**
   - 녹취록 파일(.txt, .md, .vtt, .srt, .docx)에 대한 폴더 스캔
   - 파일에 화자 레이블과 타임스탬프가 포함되어 있는지 확인
   - 회의 날짜 범위 확인
   - 녹취록에서 사용자의 이름/식별자 파악

2. **분석 목표 명확화**

   지정되지 않은 경우 무엇을 알고 싶은지 질문:
   - 특정 행동(갈등 회피, 방해, 군더더기 말)
   - 커뮤니케이션 효과성(명확성, 직접성, 경청)
   - 회의 진행 스킬
   - 발언 패턴 및 비율
   - 개선이 필요한 영역

3. **패턴 분석**

   요청된 각 인사이트에 대해:

   **갈등 회피**:
   - 회피 언어 찾기("maybe", "kind of", "I think")
   - 직접적인 요청 대신 간접적인 표현
   - 긴장이 발생할 때 주제 변경
   - 헌신 없이 동의("yeah, but...")
   - 명백한 문제를 다루지 않음

   **발언 비율**:
   - 회의에서 발언하는 데 소요된 시간 비율 계산
   - 방해 횟수(사용자에 의한 그리고 사용자에 대한) 계산
   - 평균 발언 차례 길이 측정
   - 질문 대 진술 비율 추적

   **군더더기 말**:
   - "um", "uh", "like", "you know", "actually" 등 계산
   - 분당 또는 발언 차례당 빈도 기록
   - 증가하는 상황 파악(긴장, 불확실)

   **적극적 경청**:
   - 다른 사람의 이전 요점을 참조하는 질문
   - 다른 사람의 아이디어 요약 또는 재구성
   - 다른 사람의 기여 발전시키기
   - 명확화 질문하기

   **리더십 및 진행**:
   - 의사결정 접근 방식(지시적 대 협력적)
   - 의견 불일치 처리 방법
   - 조용한 참가자 포함
   - 시간 관리 및 안건 제어
   - 후속 조치 및 실행 항목 명확성

4. **구체적인 예시 제공**

   발견된 각 패턴에 대해 다음을 포함:

   ```markdown
   ### [패턴 이름]

   **발견 사항**: [패턴에 대한 한 문장 요약]

   **빈도**: [Y개 회의에서 X번]

   **예시**:

   1. **[회의 이름/날짜]** - [타임스탬프]

      **무슨 일이 일어났는지**:
      > [녹취록의 실제 인용]

      **왜 중요한가**:
      [영향 또는 놓친 기회에 대한 설명]

      **더 나은 접근법**:
      [구체적인 대체 표현 또는 행동]

   [2-3개의 강력한 예시 반복]
   ```

5. **인사이트 종합**

   모든 패턴 분석 후 다음 제공:

   ```markdown
   # 회의 인사이트 요약

   **분석 기간**: [날짜 범위]
   **분석된 회의**: [X개 회의]
   **총 시간**: [X시간]

   ## 파악된 주요 패턴

   ### 1. [주요 패턴]
   - **관찰 내용**: [본 것]
   - **영향**: [왜 중요한지]
   - **권장 사항**: [개선 방법]

   ### 2. [두 번째 패턴]
   [동일한 구조]

   ## 커뮤니케이션 강점

   1. [예시가 있는 강점 1]
   2. [예시가 있는 강점 2]
   3. [예시가 있는 강점 3]

   ## 성장 기회

   1. **[영역 1]**: [구체적이고 실행 가능한 조언]
   2. **[영역 2]**: [구체적이고 실행 가능한 조언]
   3. **[영역 3]**: [구체적이고 실행 가능한 조언]

   ## 발언 통계

   - 평균 발언 시간: [회의의 X%]
   - 질문한 횟수: [회의당 평균 X회]
   - 군더더기 말: [분당 X개]
   - 방해: [회의당 X회 함 / Y회 받음]

   ## 다음 단계

   [커뮤니케이션을 개선하기 위한 3-5가지 구체적인 조치]
   ```

6. **후속 옵션 제공**
   - 향후 회의에서 이러한 동일한 지표 추적
   - 특정 회의 또는 패턴에 대한 심층 분석
   - 업계 벤치마크와 비교
   - 개인 커뮤니케이션 개발 계획 수립
   - 성과 평가를 위한 요약 생성

## 예시

### 예시 1: 갈등 회피 분석 (Dan Shipper의 영감을 받음)

**사용자**: "모든 회의 녹화를 다운로드하여 폴더에 넣었습니다. 제가 은밀하게 갈등을 회피한 모든 경우를 알려주세요."

**출력**:
```markdown
# 갈등 회피 패턴

15개 회의에서 간접적 커뮤니케이션을 사용하거나 긴장을 직접
다루는 것을 회피한 23개 사례를 발견했습니다.

## 패턴: 중요한 피드백에 대한 회피

**빈도**: 7개 회의에서 8번

**예시 1: Sarah와의 1:1** - 00:14:32

**무슨 일이 일어났는지**:
> "그래서, 생각해봤는데... 아마도 일정을 다시
> 검토하는 것을 잠재적으로 고려할 수 있을까요?
> 제 말은, 그게 의미가 있다고 생각하신다면요.
> 하지만 당신이 생각하는 게 최선입니다!"

**왜 중요한가**:
Sarah의 프로젝트가 일정보다 늦어진 것을 다루어야 했지만,
회피 언어("maybe", "potentially", "if you think")와
마지막 부분의 회피("whatever you think")로 인해 그녀가
긴급성을 놓치기 쉬웠습니다.

**더 나은 접근법**:
"Sarah, 프로젝트가 2주 지연되었습니다. 무엇이 진행을
막고 있는지 논의하고 오늘 새로운 일정을 만들어야 합니다."

[추가 예시...]

## 권장 사항

1. 첫 문장에서 **문제를 직접 명명**하기
2. "maybe," "kind of," "sort of"와 같은 **회피 단어 제거**
3. 암시 대신 **구체적인 질문**하기
4. 어려운 대화를 캐주얼하게 제기하는 대신 **일정 잡기**
```

### 예시 2: 리더십 진행

**사용자**: "팀 회의를 분석하고 내 진행 스타일에 대해 알려주세요."

**출력**: 다음에 대한 인사이트 제공:
- 팀원 대비 얼마나 많이 발언하는지(60% 대 40%)
- 질문을 하는지 진술을 하는지(3:1 비율)
- 의견 불일치를 처리하는 방법(너무 빨리 해결하는 경향)
- 가장 적게 말하는 사람과 그들을 끌어들이는지 여부
- 좋은 진행 순간과 놓친 순간의 예시

### 예시 3: 개인 개발 추적

**사용자**: "Q1과 Q2 회의를 비교하여 내 경청 스킬이 향상되었는지 확인해주세요."

**출력**: 다음을 보여주는 비교 분석 생성:
- 방해 감소(회의당 8회 → 3회)
- 명확화 질문 증가(회의당 2회 → 7회)
- 다른 사람의 아이디어 발전 개선
- 차이를 보여주는 구체적인 예시
- 여전히 개선이 필요한 영역

## 설정 팁

### 회의 녹취록 가져오기

**Granola에서** (Lenny의 뉴스레터 구독으로 무료):
- Granola가 회의를 자동으로 녹취
- 녹취록을 폴더로 내보내기: [방법에 대한 지침]
- Claude Code를 해당 폴더로 지정

**Zoom에서**:
- 녹취와 함께 클라우드 녹화 활성화
- 회의 후 VTT 또는 SRT 파일 다운로드
- 전용 폴더에 저장

**Google Meet에서**:
- Google Docs 자동 녹취 사용
- 녹취록 문서를 폴더에 저장
- .txt 파일로 다운로드하거나 Claude Code에 액세스 권한 부여

**Fireflies.ai, Otter.ai 등에서**:
- 녹취록을 일괄 내보내기
- 로컬 폴더에 저장
- 폴더에서 분석 실행

### 모범 사례

1. **일관된 이름 지정**: `YYYY-MM-DD - 회의 이름.txt` 형식 사용
2. **정기적인 분석**: 추세를 파악하기 위해 월별 또는 분기별로 검토
3. **구체적인 쿼리**: 깊이를 위해 한 번에 하나의 행동에 대해 질문
4. **개인정보 보호**: 민감한 회의 데이터를 로컬에 보관
5. **행동 지향적**: 한 번에 하나의 개선 영역에 집중

- 인사이트로부터 개인 개발 계획 수립
- 예시를 통한 성과 평가 자료 준비
- 커뮤니케이션에 대한 직속 부하 직원 코칭
- 영업 또는 지원 패턴에 대한 고객 통화 분석
- 협상 전술 및 결과 연구
