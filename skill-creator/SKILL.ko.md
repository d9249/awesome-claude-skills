# 스킬 생성기

이 스킬은 효과적인 스킬을 만들기 위한 지침을 제공합니다.

## 스킬에 대하여

스킬은 전문 지식, 워크플로 및 도구를 제공하여 Claude의 기능을 확장하는 모듈식의 독립적인 패키지입니다. 특정 도메인이나 작업을 위한 "온보딩 가이드"로 생각하세요. 스킬은 Claude를 범용 에이전트에서 어떤 모델도 완전히 소유할 수 없는 절차적 지식을 갖춘 전문 에이전트로 변환합니다.

### 스킬이 제공하는 것

1. 전문화된 워크플로 - 특정 도메인을 위한 다단계 절차
2. 도구 통합 - 특정 파일 형식 또는 API 작업을 위한 지침
3. 도메인 전문성 - 회사별 지식, 스키마, 비즈니스 로직
4. 번들 리소스 - 복잡하고 반복적인 작업을 위한 스크립트, 참조 자료 및 에셋

### 스킬의 구조

모든 스킬은 필수 SKILL.md 파일과 선택적 번들 리소스로 구성됩니다:

```
skill-name/
├── SKILL.md (필수)
│   ├── YAML frontmatter 메타데이터 (필수)
│   │   ├── name: (필수)
│   │   └── description: (필수)
│   └── Markdown 지침 (필수)
└── 번들 리소스 (선택)
    ├── scripts/          - 실행 가능한 코드 (Python/Bash 등)
    ├── references/       - 필요에 따라 컨텍스트에 로드되는 문서
    └── assets/           - 출력에 사용되는 파일 (템플릿, 아이콘, 폰트 등)
```

#### SKILL.md (필수)

**메타데이터 품질:** YAML frontmatter의 `name`과 `description`은 Claude가 스킬을 사용할 시기를 결정합니다. 스킬이 무엇을 하고 언제 사용하는지 구체적으로 작성하세요. 3인칭을 사용하세요(예: "이 스킬을 사용하세요..." 대신 "이 스킬은 ... 할 때 사용해야 합니다").

#### 번들 리소스 (선택)

##### 스크립트 (`scripts/`)

결정적 신뢰성이 필요하거나 반복적으로 다시 작성되는 작업을 위한 실행 가능한 코드(Python/Bash 등).

- **포함해야 할 때**: 동일한 코드가 반복적으로 다시 작성되거나 결정적 신뢰성이 필요할 때
- **예시**: PDF 회전 작업을 위한 `scripts/rotate_pdf.py`
- **이점**: 토큰 효율적, 결정적, 컨텍스트에 로드하지 않고 실행 가능
- **참고**: 패치 또는 환경별 조정을 위해 여전히 Claude가 스크립트를 읽어야 할 수 있음

##### 참조 자료 (`references/`)

Claude의 프로세스와 사고를 알리기 위해 필요에 따라 컨텍스트에 로드되는 문서 및 참조 자료.

- **포함해야 할 때**: 작업 중 Claude가 참조해야 하는 문서의 경우
- **예시**: 금융 스키마를 위한 `references/finance.md`, 회사 NDA 템플릿을 위한 `references/mnda.md`, 회사 정책을 위한 `references/policies.md`, API 사양을 위한 `references/api_docs.md`
- **사용 사례**: 데이터베이스 스키마, API 문서, 도메인 지식, 회사 정책, 상세한 워크플로 가이드
- **이점**: SKILL.md를 간결하게 유지, Claude가 필요하다고 판단할 때만 로드
- **모범 사례**: 파일이 큰 경우(>10k 단어), SKILL.md에 grep 검색 패턴 포함
- **중복 방지**: 정보는 SKILL.md 또는 참조 파일 중 하나에만 있어야 하며 둘 다에 있으면 안 됩니다. 정말로 스킬의 핵심이 아닌 경우 상세 정보는 참조 파일을 선호하세요. 이렇게 하면 SKILL.md를 간결하게 유지하면서 컨텍스트 창을 차지하지 않고 정보를 검색할 수 있습니다. SKILL.md에는 필수 절차 지침과 워크플로 안내만 유지하고, 상세 참조 자료, 스키마 및 예시는 참조 파일로 이동하세요.

##### 에셋 (`assets/`)

컨텍스트에 로드되지 않고 Claude가 생성하는 출력 내에서 사용되는 파일.

- **포함해야 할 때**: 스킬이 최종 출력에서 사용될 파일이 필요한 경우
- **예시**: 브랜드 에셋을 위한 `assets/logo.png`, PowerPoint 템플릿을 위한 `assets/slides.pptx`, HTML/React 보일러플레이트를 위한 `assets/frontend-template/`, 타이포그래피를 위한 `assets/font.ttf`
- **사용 사례**: 복사되거나 수정되는 템플릿, 이미지, 아이콘, 보일러플레이트 코드, 폰트, 샘플 문서
- **이점**: 출력 리소스를 문서와 분리하여 Claude가 컨텍스트에 로드하지 않고 파일을 사용할 수 있음

### 점진적 공개 설계 원칙

스킬은 컨텍스트를 효율적으로 관리하기 위해 3단계 로딩 시스템을 사용합니다:

1. **메타데이터 (name + description)** - 항상 컨텍스트에 있음 (~100 단어)
2. **SKILL.md 본문** - 스킬이 트리거될 때 (<5k 단어)
3. **번들 리소스** - Claude가 필요에 따라 (무제한*)

*스크립트는 컨텍스트 창에 읽지 않고 실행할 수 있으므로 무제한입니다.

## 스킬 생성 프로세스

스킬을 만들려면 "스킬 생성 프로세스"를 순서대로 따르되, 적용되지 않는 명확한 이유가 있는 경우에만 단계를 건너뛰세요.

### 1단계: 구체적인 예시로 스킬 이해하기

스킬의 사용 패턴이 이미 명확하게 이해된 경우에만 이 단계를 건너뛰세요. 기존 스킬을 작업하는 경우에도 유용합니다.

효과적인 스킬을 만들려면 스킬이 어떻게 사용될지 구체적인 예시를 명확하게 이해하세요. 이 이해는 직접적인 사용자 예시 또는 사용자 피드백으로 검증된 생성된 예시에서 올 수 있습니다.

예를 들어, image-editor 스킬을 구축할 때 관련 질문은 다음과 같습니다:

- "image-editor 스킬은 어떤 기능을 지원해야 하나요? 편집, 회전, 그 외 다른 것은?"
- "이 스킬이 어떻게 사용될지 예시를 들어줄 수 있나요?"
- "사용자가 '이 이미지에서 적목 현상 제거' 또는 '이 이미지 회전'과 같은 것을 요청하는 것을 상상할 수 있습니다. 이 스킬이 사용될 다른 방법이 있나요?"
- "이 스킬을 트리거해야 하는 사용자의 말은 무엇인가요?"

사용자를 압도하지 않으려면 한 메시지에 너무 많은 질문을 하지 마세요. 가장 중요한 질문부터 시작하고 더 나은 효과를 위해 필요에 따라 후속 조치하세요.

스킬이 지원해야 하는 기능에 대한 명확한 감각이 있을 때 이 단계를 완료하세요.

### 2단계: 재사용 가능한 스킬 콘텐츠 계획하기

구체적인 예시를 효과적인 스킬로 전환하려면 각 예시를 다음과 같이 분석하세요:

1. 처음부터 예시를 실행하는 방법 고려
2. 이러한 워크플로를 반복적으로 실행할 때 도움이 될 스크립트, 참조 자료 및 에셋 식별

예시: "이 PDF 회전을 도와주세요"와 같은 쿼리를 처리하기 위해 `pdf-editor` 스킬을 구축할 때 분석 결과:

1. PDF 회전은 매번 동일한 코드를 다시 작성해야 함
2. `scripts/rotate_pdf.py` 스크립트가 스킬에 저장하는 데 유용함

예시: "할 일 앱 만들어줘" 또는 "걸음 수를 추적하는 대시보드 만들어줘"와 같은 쿼리를 위한 `frontend-webapp-builder` 스킬을 설계할 때 분석 결과:

1. 프론트엔드 웹앱을 작성하려면 매번 동일한 보일러플레이트 HTML/React가 필요함
2. 보일러플레이트 HTML/React 프로젝트 파일을 포함하는 `assets/hello-world/` 템플릿이 스킬에 저장하는 데 유용함

예시: "오늘 로그인한 사용자는 몇 명인가요?"와 같은 쿼리를 처리하기 위해 `big-query` 스킬을 구축할 때 분석 결과:

1. BigQuery 쿼리는 매번 테이블 스키마와 관계를 다시 발견해야 함
2. 테이블 스키마를 문서화하는 `references/schema.md` 파일이 스킬에 저장하는 데 유용함

스킬의 콘텐츠를 확립하려면 각 구체적인 예시를 분석하여 포함할 재사용 가능한 리소스 목록을 만드세요: 스크립트, 참조 자료 및 에셋.

### 3단계: 스킬 초기화하기

이 시점에서 실제로 스킬을 만들 시간입니다.

개발 중인 스킬이 이미 존재하고 반복 또는 패키징이 필요한 경우에만 이 단계를 건너뛰세요. 이 경우 다음 단계로 계속하세요.

처음부터 새 스킬을 만들 때는 항상 `init_skill.py` 스크립트를 실행하세요. 스크립트는 스킬에 필요한 모든 것을 자동으로 포함하는 새 템플릿 스킬 디렉토리를 편리하게 생성하여 스킬 생성 프로세스를 훨씬 더 효율적이고 신뢰할 수 있게 만듭니다.

사용법:

```bash
scripts/init_skill.py <skill-name> --path <output-directory>
```

스크립트는:

- 지정된 경로에 스킬 디렉토리 생성
- 적절한 frontmatter와 TODO 플레이스홀더가 있는 SKILL.md 템플릿 생성
- 예시 리소스 디렉토리 생성: `scripts/`, `references/`, `assets/`
- 각 디렉토리에 사용자 정의하거나 삭제할 수 있는 예시 파일 추가

초기화 후 필요에 따라 생성된 SKILL.md 및 예시 파일을 사용자 정의하거나 제거하세요.

### 4단계: 스킬 편집하기

(새로 생성되거나 기존) 스킬을 편집할 때, 다른 Claude 인스턴스가 사용할 스킬을 만들고 있다는 점을 기억하세요. 다른 Claude 인스턴스에게 유익하고 명확하지 않은 정보를 포함하는 데 집중하세요. 다른 Claude 인스턴스가 이러한 작업을 더 효과적으로 수행하는 데 도움이 될 절차적 지식, 도메인별 세부 사항 또는 재사용 가능한 에셋을 고려하세요.

#### 재사용 가능한 스킬 콘텐츠부터 시작

구현을 시작하려면 위에서 식별한 재사용 가능한 리소스부터 시작하세요: `scripts/`, `references/`, `assets/` 파일. 이 단계에서는 사용자 입력이 필요할 수 있습니다. 예를 들어, `brand-guidelines` 스킬을 구현할 때 사용자는 `assets/`에 저장할 브랜드 에셋이나 템플릿, 또는 `references/`에 저장할 문서를 제공해야 할 수 있습니다.

또한 스킬에 필요하지 않은 예시 파일과 디렉토리를 삭제하세요. 초기화 스크립트는 구조를 보여주기 위해 `scripts/`, `references/`, `assets/`에 예시 파일을 만들지만 대부분의 스킬은 모두 필요하지 않습니다.

#### SKILL.md 업데이트

**작성 스타일:** 2인칭이 아닌 **명령형/부정사 형태**(동사가 먼저 나오는 지침)를 사용하여 전체 스킬을 작성하세요. 객관적이고 교육적인 언어를 사용하세요(예: "당신은 X를 해야 합니다" 또는 "X를 해야 한다면" 대신 "X를 수행하려면 Y를 하세요"). 이는 AI 소비를 위한 일관성과 명확성을 유지합니다.

SKILL.md를 완성하려면 다음 질문에 답하세요:

1. 스킬의 목적은 무엇인가요? 몇 문장으로 설명하세요.
2. 스킬은 언제 사용해야 하나요?
3. 실제로 Claude는 스킬을 어떻게 사용해야 하나요? 위에서 개발한 모든 재사용 가능한 스킬 콘텐츠는 Claude가 사용 방법을 알 수 있도록 참조되어야 합니다.

### 5단계: 스킬 패키징하기

스킬이 준비되면 사용자와 공유할 배포 가능한 zip 파일로 패키징해야 합니다. 패키징 프로세스는 모든 요구 사항을 충족하는지 확인하기 위해 먼저 스킬을 자동으로 검증합니다:

```bash
scripts/package_skill.py <path/to/skill-folder>
```

선택적 출력 디렉토리 지정:

```bash
scripts/package_skill.py <path/to/skill-folder> ./dist
```

패키징 스크립트는:

1. **스킬을 자동으로 검증**하여 다음을 확인합니다:
   - YAML frontmatter 형식 및 필수 필드
   - 스킬 명명 규칙 및 디렉토리 구조
   - 설명 완전성 및 품질
   - 파일 구성 및 리소스 참조

2. 검증이 통과되면 **스킬을 패키징**하여 스킬 이름을 따서 명명된 zip 파일(예: `my-skill.zip`)을 만들고 모든 파일을 포함하며 배포를 위한 적절한 디렉토리 구조를 유지합니다.

검증이 실패하면 스크립트는 오류를 보고하고 패키지를 만들지 않고 종료합니다. 검증 오류를 수정하고 패키징 명령을 다시 실행하세요.

### 6단계: 반복

스킬을 테스트한 후 사용자는 개선을 요청할 수 있습니다. 종종 이는 스킬을 사용한 직후 스킬이 어떻게 수행되었는지에 대한 새로운 컨텍스트와 함께 발생합니다.

**반복 워크플로:**
1. 실제 작업에 스킬 사용
2. 어려움이나 비효율성 발견
3. SKILL.md 또는 번들 리소스를 어떻게 업데이트해야 하는지 식별
4. 변경 사항을 구현하고 다시 테스트
