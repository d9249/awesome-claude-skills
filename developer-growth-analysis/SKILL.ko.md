# Developer Growth Analysis

이 스킬은 Claude Code 채팅 상호 작용을 분석하여 강점과 성장 영역을 드러내는 패턴을 식별함으로써 최근 코딩 작업에 대한 개인화된 피드백을 제공합니다.

## 이 스킬을 사용하는 경우

이 스킬은 다음을 원할 때 사용하세요:
- 최근 작업에서 개발 패턴과 습관 이해
- 특정 기술 격차 또는 반복되는 과제 식별
- 더 깊은 학습이 도움이 될 주제 발견
- 실제 작업 패턴에 맞춤화된 선별된 학습 리소스 얻기
- 최근 프로젝트에서 개선 영역 추적
- 개발 중인 기술을 직접 다루는 고품질 기사 찾기

이 스킬은 코드 리뷰를 기다리지 않고 성장에 대한 구조화된 피드백을 원하고 자신의 작업 이력에서 데이터 기반 인사이트를 선호하는 개발자에게 이상적입니다.

## 이 스킬이 하는 일

이 스킬은 개발 작업에 대한 6단계 분석을 수행합니다:

1. **채팅 기록 읽기**: 지난 24-48시간 동안의 로컬 Claude Code 채팅 기록에 액세스하여 작업 내용을 이해합니다.

2. **개발 패턴 식별**: 해결하는 문제 유형, 사용하는 기술, 직면한 과제 및 다양한 유형의 작업에 접근하는 방법을 분석합니다.

3. **개선 영역 감지**: 기술 격차, 반복되는 어려움, 비효율적인 접근 방식 또는 더 깊은 지식이 도움이 될 영역을 제안하는 패턴을 인식합니다.

4. **개인화된 보고서 생성**: 작업 요약, 식별된 개선 영역 및 성장을 위한 구체적인 권장 사항을 보여주는 포괄적인 보고서를 만듭니다.

5. **학습 리소스 찾기**: HackerNews를 사용하여 개선 영역과 직접 관련된 고품질 기사 및 토론을 선별하여 실제 개발 작업에 맞춤화된 읽기 목록을 제공합니다.

6. **Slack DM으로 전송**: 언제 어디서나 참조할 수 있도록 완전한 보고서를 자신의 Slack 다이렉트 메시지로 자동 전달합니다.

## 사용 방법

Claude에게 최근 코딩 작업 분석을 요청하세요:

```
최근 채팅에서 내 개발자 성장 분석
```

또는 어떤 기간에 대해 더 구체적으로 지정:

```
오늘 작업을 분석하고 개선 영역 제안
```

스킬은 다음과 같은 형식의 보고서를 생성합니다:
- 최근 작업 개요
- 식별된 주요 개선 영역
- 각 영역에 대한 구체적인 권장 사항
- HackerNews에서 선별된 학습 리소스
- 집중할 수 있는 실행 항목

## 지침

사용자가 최근 작업에서 개발자 성장 또는 코딩 패턴 분석을 요청할 때:

1. **채팅 기록 액세스**

   `~/.claude/history.jsonl`에서 채팅 기록을 읽습니다. 이 파일은 각 줄에 다음을 포함하는 JSONL 형식입니다:
   - `display`: 사용자의 메시지/요청
   - `project`: 작업 중인 프로젝트
   - `timestamp`: Unix 타임스탬프 (밀리초 단위)
   - `pastedContents`: 붙여넣은 코드 또는 콘텐츠

   현재 타임스탬프를 기반으로 지난 24-48시간 동안의 항목을 필터링합니다.

2. **작업 패턴 분석**

   필터링된 채팅에서 다음을 추출하고 분석:
   - **프로젝트 및 도메인**: 사용자가 작업한 프로젝트 유형은? (예: 백엔드, 프론트엔드, DevOps, 데이터 등)
   - **사용된 기술**: 대화에 나타나는 언어, 프레임워크 및 도구는?
   - **문제 유형**: 해결되는 문제의 범주는? (예: 성능 최적화, 디버깅, 기능 구현, 리팩토링, 설정/구성)
   - **직면한 과제**: 사용자가 어려움을 겪은 문제는? 다음을 찾으세요:
     - 유사한 주제에 대한 반복된 질문
     - 여러 시도가 필요한 문제
     - 지식 격차를 나타내는 질문
     - 복잡한 아키텍처 결정
   - **접근 패턴**: 사용자가 문제를 해결하는 방법은? (예: 체계적, 탐색적, 실험적)

3. **개선 영역 식별**

   분석을 기반으로 사용자가 개선할 수 있는 3-5개의 구체적인 영역을 식별합니다. 이것들은 다음과 같아야 합니다:
   - **구체적** ("코딩 기술 향상"과 같이 모호하지 않음)
   - **증거 기반** (실제 채팅 기록에 근거)
   - **실행 가능** (실용적인 개선 가능)
   - **우선순위 지정** (가장 영향력 있는 것부터)

   좋은 개선 영역의 예:
   - "고급 TypeScript 패턴 (제네릭, 유틸리티 타입, 타입 가드) - [특정 프로젝트]에서 타입 안전성으로 어려움을 겪었습니다"
   - "오류 처리 및 유효성 검사 - 누락된 null 체크와 관련된 여러 버그를 패치한 것을 확인했습니다"
   - "비동기/대기 패턴 - 최근 작업에서 일부 경쟁 조건 및 타이밍 문제를 보여줍니다"
   - "데이터베이스 쿼리 최적화 - 같은 쿼리를 여러 번 다시 작성했습니다"

4. **보고서 생성**

   이 구조로 포괄적인 보고서 작성:

   ```markdown
   # 개발자 성장 보고서

   **보고서 기간**: [어제 / 오늘 / [사용자 정의 날짜 범위]]
   **마지막 업데이트**: [현재 날짜 및 시간]

   ## 작업 요약

   [사용자가 작업한 내용, 다룬 프로젝트, 사용한 기술 및 전체 초점 영역을 요약한 2-3단락]

   예:
   "지난 24시간 동안 세 가지 별개의 프로젝트로 주로 백엔드 개발에 집중했습니다. 작업에는 TypeScript, React 및 배포 인프라가 포함되었습니다. 기능 구현, 디버깅 및 아키텍처 결정을 혼합하여 처리했으며, API 디자인 및 데이터베이스 최적화에 특히 집중했습니다."

   ## 개선 영역 (우선순위)

   ### 1. [영역 이름]

   **중요한 이유**: [이 기술이 사용자의 작업에 중요한 이유 설명]

   **관찰한 내용**: [이 격차를 보여주는 채팅 기록의 구체적인 증거]

   **권장 사항**: [이 영역에서 개선하기 위한 구체적인 단계]

   **스킬업 시간**: [필요한 노력의 간략한 추정]

   ---

   [2-4개의 추가 영역에 대해 반복]

   ## 관찰된 강점

   [잘 하고 있는 것 - 계속해야 할 것에 대한 2-3개의 불릿 포인트]

   ## 실행 항목

   우선순위 순서:
   1. [최우선 개선 영역에서 파생된 실행 항목]
   2. [다음 영역의 실행 항목]
   3. [다음 영역의 실행 항목]

   ## 학습 리소스

   [다음 단계에서 채워질 예정]
   ```

5. **학습 리소스 검색**

   Rube MCP를 사용하여 각 개선 영역과 관련된 HackerNews 기사 검색:

   - 각 개선 영역에 대해 고품질 리소스를 대상으로 하는 검색 쿼리 구성
   - RUBE_SEARCH_TOOLS를 사용하여 HackerNews 검색, 쿼리 예:
     - "Learn [기술/패턴] best practices"
     - "[기술] 고급 패턴 및 기법"
     - "[언어]에서 [특정 문제 유형] 디버깅"
   - 높은 참여도(댓글, 업보트)를 가진 게시물 우선순위 지정
   - 각 영역에 대해 가장 관련성 있는 2-3개의 기사 포함:
     - 기사 제목
     - 게시 날짜
     - 관련성에 대한 간략한 설명
     - 기사 링크

   보고서에 이 섹션 추가:

   ```markdown
   ## 선별된 학습 리소스

   ### 대상: [개선 영역]

   1. **[기사 제목]** - [날짜]
      [다루는 내용과 개선 영역과의 관련성에 대한 설명]
      [링크]

   2. **[기사 제목]** - [날짜]
      [설명]
      [링크]

   [다른 개선 영역에 대해 반복]
   ```

6. **완전한 보고서 제시**

   사용자가 다음을 할 수 있는 깔끔하고 읽기 쉬운 형식으로 보고서 전달:
   - 핵심 요점을 빠르게 스캔
   - 집중된 학습 계획에 사용
   - 개선 작업을 하는 다음 주 동안 참조
   - 원하는 경우 멘토와 공유하여 외부 피드백 받기

7. **Slack DM으로 보고서 전송**

   Rube MCP를 사용하여 완전한 보고서를 사용자 자신의 Slack DM으로 전송:

   - RUBE_SEARCH_TOOLS를 통해 Slack 연결이 활성화되어 있는지 확인
   - 연결되지 않은 경우 RUBE_MANAGE_CONNECTIONS를 사용하여 Slack 인증 시작
   - RUBE_MULTI_EXECUTE_TOOL을 사용하여 보고서를 형식이 지정된 메시지로 전송:
     - 보고서 제목과 기간을 첫 번째 메시지로 전송
     - 보고서를 논리적 섹션으로 분할 (요약, 개선 사항, 강점, 실행, 리소스)
     - 각 섹션을 적절한 마크다운으로 잘 구조화된 Slack 메시지로 포맷팅
     - 학습 리소스에 대한 클릭 가능한 링크 포함
   - CLI 출력에서 전달 확인

   이렇게 하면 사용자가 정기적으로 확인하는 장소에 보고서가 있고 일주일 내내 참조할 수 있습니다.

## 사용 예시

### 입력

```
최근 채팅에서 내 개발자 성장 분석
```

### 출력

```markdown
# 개발자 성장 보고서

**보고서 기간**: 2024년 11월 9-10일
**마지막 업데이트**: 2024년 11월 10일, 오후 9:15 UTC

## 작업 요약

지난 이틀 동안 백엔드 인프라 및 API 개발에 집중했습니다. 주요 프로젝트는 오픈 소스 쇼케이스 애플리케이션으로, 연결 관리, UI 개선 및 배포 구성에 상당한 진전을 이뤘습니다. TypeScript, React 및 Node.js로 작업하여 데이터 보안에서 반응형 디자인까지의 과제를 다뤘습니다. 작업은 기능 구현과 기술 부채 처리 간의 균형을 보여줍니다.

## 개선 영역 (우선순위)

### 1. 고급 TypeScript 패턴 및 타입 안전성

**중요한 이유**: TypeScript는 작업의 중심이지만, 고급 기능(제네릭, 유틸리티 타입, 조건부 타입, 타입 가드)을 활용하면 코드 신뢰성을 크게 향상시키고 런타임 오류를 줄일 수 있습니다. 더 나은 타입 안전성은 프로덕션이 아닌 컴파일 타임에 버그를 포착합니다.

**관찰한 내용**: 최근 채팅에서 연결 데이터 구조로 작업하고 있었고 인증 구성을 적절하게 타이핑하는 데 몇 번 어려움을 겪었습니다. 또한 다양한 연결 상태에 대한 유니온 타입을 반복했습니다. 판별된 유니온과 타입 가드를 더 효과적으로 사용할 기회가 있습니다.

**권장 사항**: TypeScript의 고급 타입 시스템, 특히 유틸리티 타입(Omit, Pick, Record), 조건부 타입 및 판별된 유니온을 학습하세요. 이러한 패턴을 연결 구성 처리 및 인증 상태 관리에 적용하세요.

**스킬업 시간**: 집중 학습 및 연습 5-8시간

### 2. UI에서 안전한 데이터 처리 및 정보 숨김

**중요한 이유**: 콘솔에 민감한 연결 데이터가 표시되는 보안 문제를 식별하고 수정했습니다. 정보 유출 방지는 사용자 자격 증명 및 API 키를 처리하는 애플리케이션에 중요합니다. 여기서 좋은 관행은 보안 사고와 사용자 신뢰 위반을 방지합니다.

**관찰한 내용**: "Your Apps" 페이지가 인증 구성을 포함한 전체 연결 데이터를 표시하고 있다는 것을 발견했습니다. 이것은 좋은 보안 본능을 보여주며, 다음 단계는 민감한 정보를 처리할 때 이를 기본 사고로 구축하는 것입니다.

**권장 사항**: 프론트엔드 애플리케이션에서 민감한 데이터를 처리하기 위한 보안 모범 사례를 검토하세요. 표시하기 전에 민감한 정보를 필터링/마스킹하기 위한 재사용 가능한 패턴을 만드세요. UI에 표시될 수 있는 것을 명시적으로 화이트리스트하는 안전한 데이터 레이어 구현을 고려하세요.

**스킬업 시간**: 3-4시간

### 3. 컴포넌트 아키텍처 및 반응형 UI 패턴

**중요한 이유**: 다양한 화면 크기와 사용자 상호 작용에서 작동해야 하는 UI를 디자인하고 있습니다. 강력한 컴포넌트 아키텍처는 버그 없이 복잡한 UI를 구축하기 쉽게 하고 유지 관리성을 향상시킵니다.

**관찰한 내용**: 디자인 이미지에서 "Marketplace" UI (이전 Browse Tools)를 재작성하는 작업을 했습니다. 또한 콘텐츠가 컨테이너를 오버플로하는 스크롤 문제를 식별하고 수정했습니다. 레이아웃 포함 및 반응형 디자인 패턴에 대한 이해를 강화할 기회가 있습니다.

**권장 사항**: React 컴포넌트 구성 패턴 및 CSS 레이아웃 모범 사례(특히 flexbox 및 grid)를 학습하세요. 오버플로 문제를 방지하는 컨테이너 쿼리 및 반응형 패턴에 집중하세요. 컴포넌트 구성 라이브러리 및 디자인 시스템 접근 방식을 살펴보세요.
```
