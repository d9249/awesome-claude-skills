# Content Research Writer

이 스킬은 당신의 작성 파트너로서 고유한 목소리와 스타일을 유지하면서 콘텐츠를 조사하고, 개요를 작성하며, 초안을 작성하고, 다듬는 데 도움을 줍니다.

## 이 스킬을 사용하는 경우

- 블로그 게시물, 기사 또는 뉴스레터 작성
- 교육 콘텐츠 또는 튜토리얼 생성
- 사고 리더십 작품 초안 작성
- 사례 연구 조사 및 작성
- 출처가 있는 기술 문서 작성
- 적절한 인용과 참조로 작성
- 후크 및 소개 개선
- 작성하는 동안 섹션별 피드백 받기

## 이 스킬이 하는 일

1. **협업적 개요 작성**: 아이디어를 일관된 개요로 구조화하는 데 도움
2. **조사 지원**: 관련 정보를 찾고 인용 추가
3. **후크 개선**: 주목을 끌기 위해 오프닝 강화
4. **섹션 피드백**: 작성하는 각 섹션 검토
5. **목소리 보존**: 작성 스타일과 톤 유지
6. **인용 관리**: 참조를 적절하게 추가하고 포맷팅
7. **반복적 개선**: 여러 초안을 통해 개선하는 데 도움

## 사용 방법

### 작성 환경 설정

기사를 위한 전용 폴더 생성:
```
mkdir ~/writing/my-article-title
cd ~/writing/my-article-title
```

초안 파일 생성:
```
touch article-draft.md
```

이 디렉토리에서 Claude Code를 열고 작성을 시작하세요.

### 기본 워크플로우

1. **개요로 시작**:
```
[주제]에 대한 기사 개요 작성을 도와주세요
```

2. **조사하고 인용 추가**:
```
[특정 주제]를 조사하고 내 개요에 인용 추가
```

3. **후크 개선**:
```
여기 내 소개가 있습니다. 후크를 더 매력적으로 만드는 데 도움을 주세요.
```

4. **섹션 피드백 받기**:
```
방금 "이것이 중요한 이유" 섹션을 완료했습니다. 검토하고 피드백을 주세요.
```

5. **다듬고 광택 내기**:
```
흐름, 명확성 및 일관성을 위해 전체 초안 검토
```

## 지침

사용자가 작성 지원을 요청할 때:

1. **작성 프로젝트 이해**

   명확한 질문:
   - 주제와 주요 주장은 무엇인가요?
   - 타겟 대상은 누구인가요?
   - 원하는 길이/형식은?
   - 목표는 무엇인가요? (교육, 설득, 오락, 설명)
   - 포함할 기존 조사 또는 출처가 있나요?
   - 작성 스타일은 무엇인가요? (공식적, 대화형, 기술적)

2. **협업적 개요 작성**

   콘텐츠 구조화를 도와주세요:

   ```markdown
   # 기사 개요: [제목]

   ## 후크
   - [오프닝 라인/스토리/통계]
   - [독자가 관심을 가져야 하는 이유]

   ## 소개
   - 맥락과 배경
   - 문제 진술
   - 이 기사가 다루는 내용

   ## 주요 섹션

   ### 섹션 1: [제목]
   - 핵심 포인트 A
   - 핵심 포인트 B
   - 예시/증거
   - [필요한 조사: 특정 주제]

   ### 섹션 2: [제목]
   - 핵심 포인트 C
   - 핵심 포인트 D
   - 데이터/인용 필요

   ### 섹션 3: [제목]
   - 핵심 포인트 E
   - 반대 주장
   - 해결책

   ## 결론
   - 주요 포인트 요약
   - 행동 유도
   - 최종 생각

   ## 조사 할 일
   - [ ] [주제]에 대한 데이터 찾기
   - [ ] [개념]의 예시 가져오기
   - [ ] [주장]에 대한 출처 인용
   ```

   **개요 반복**:
   - 피드백을 기반으로 조정
   - 논리적 흐름 확인
   - 조사 격차 식별
   - 심층 분석을 위한 섹션 표시

3. **조사 수행**

   사용자가 주제에 대한 조사를 요청할 때:

   - 관련 정보 검색
   - 신뢰할 수 있는 출처 찾기
   - 주요 사실, 인용문 및 데이터 추출
   - 요청된 형식으로 인용 추가

   예시 출력:
   ```markdown
   ## 조사: 생산성에 대한 AI의 영향

   주요 발견 사항:

   1. **생산성 향상**: 연구에 따르면 콘텐츠 생성 작업에 대해
      40% 시간 절약 [1]

   2. **채택률**: 지식 근로자의 67%가 AI 도구를
      매주 사용 [2]

   3. **전문가 인용**: "AI는 인간 창의성을 대체하기보다는
      증강합니다" - Dr. Jane Smith, MIT [3]

   인용:
   [1] McKinsey Global Institute. (2024). "생성 AI의 경제적 잠재력"
   [2] Stack Overflow 개발자 설문조사 (2024)
   [3] Smith, J. (2024). MIT Technology Review 인터뷰

   섹션 2 아래 개요에 추가됨.
   ```

4. **후크 개선**

   사용자가 소개를 공유할 때 분석하고 강화:

   **현재 후크 분석**:
   - 효과적인 것: [긍정적인 요소]
   - 더 강화할 수 있는 것: [개선 영역]
   - 감정적 영향: [현재 대 잠재력]

   **제안된 대안**:

   옵션 1: [대담한 진술]
   > [예시]
   *효과적인 이유: [설명]*

   옵션 2: [개인적인 스토리]
   > [예시]
   *효과적인 이유: [설명]*

   옵션 3: [놀라운 데이터]
   > [예시]
   *효과적인 이유: [설명]*

   **후크를 위한 질문**:
   - 호기심을 자극하나요?
   - 가치를 약속하나요?
   - 충분히 구체적인가요?
   - 대상과 일치하나요?

5. **섹션별 피드백 제공**

   사용자가 각 섹션을 작성할 때 다음을 검토:

   ```markdown
   # 피드백: [섹션 이름]

   ## 잘 작동하는 것 ✓
   - [강점 1]
   - [강점 2]
   - [강점 3]

   ## 개선 제안

   ### 명확성
   - [특정 문제] → [제안된 수정]
   - [복잡한 문장] → [더 간단한 대안]

   ### 흐름
   - [전환 문제] → [더 나은 연결]
   - [단락 순서] → [제안된 재정렬]

   ### 증거
   - [지원이 필요한 주장] → [인용 또는 예시 추가]
   - [일반적인 진술] → [더 구체적으로 만들기]

   ### 스타일
   - [톤 불일치] → [목소리와 더 잘 일치]
   - [단어 선택] → [더 강한 대안]

   ## 구체적인 라인 편집

   원본:
   > [초안의 정확한 인용]

   제안:
   > [개선된 버전]

   이유: [설명]

   ## 고려할 질문
   - [생각을 자극하는 질문 1]
   - [생각을 자극하는 질문 2]

   다음 섹션으로 이동할 준비 완료!
   ```

6. **작성자의 목소리 보존**

   중요한 원칙:

   - **스타일 학습**: 기존 작성 샘플 읽기
   - **제안, 대체 아님**: 지시가 아닌 옵션 제공
   - **톤 일치**: 공식적, 캐주얼, 기술적, 친근한
   - **선택 존중**: 그들이 자신의 버전을 선호하면 지원
   - **향상, 재정의 아님**: 그들의 작성을 다르게가 아닌 더 좋게

   주기적으로 질문:
   - "이것이 당신처럼 들리나요?"
   - "이것이 올바른 톤인가요?"
   - "더/덜 [공식적/캐주얼/기술적]이어야 하나요?"

7. **인용 관리**

   사용자 선호도에 따라 참조 처리:

   **인라인 인용**:
   ```markdown
   연구에 따르면 40% 생산성 향상 (McKinsey, 2024).
   ```

   **번호 참조**:
   ```markdown
   연구에 따르면 40% 생산성 향상 [1].

   [1] McKinsey Global Institute. (2024)...
   ```

   **각주 스타일**:
   ```markdown
   연구에 따르면 40% 생산성 향상^1

   ^1: McKinsey Global Institute. (2024)...
   ```

   실행 중인 인용 목록 유지:
   ```markdown
   ## 참고 문헌

   1. Author. (Year). "Title". Publication.
   2. Author. (Year). "Title". Publication.
   ...
   ```

8. **최종 검토 및 광택**

   초안이 완료되면 포괄적인 피드백 제공:

   ```markdown
   # 전체 초안 검토

   ## 전체 평가

   **강점**:
   - [주요 강점 1]
   - [주요 강점 2]
   - [주요 강점 3]

   **영향**: [전체 효과 평가]

   ## 구조 및 흐름
   - [조직에 대한 코멘트]
   - [전환 품질]
   - [페이싱 평가]

   ## 콘텐츠 품질
   - [주장 강도]
   - [증거 충분성]
   - [예시 효과]

   ## 기술적 품질
   - 문법 및 역학: [평가]
   - 일관성: [평가]
   - 인용: [완전성 확인]

   ## 가독성
   - 명확성 점수: [평가]
   - 문장 다양성: [평가]
   - 단락 길이: [평가]

   ## 최종 광택 제안

   1. **소개**: [구체적인 개선]
   2. **본문**: [구체적인 개선]
   3. **결론**: [구체적인 개선]
   4. **제목**: [필요시 옵션]

   ## 게시 전 체크리스트
   - [ ] 모든 주장 출처 확인
   - [ ] 인용 포맷팅
   - [ ] 예시 명확
   - [ ] 전환 부드러움
   - [ ] 행동 유도 존재
   - [ ] 오타 교정

   게시 준비 완료! 🚀
   ```

## 예시

### 예시 1: Teresa Torres의 워크플로우

**사용자**: "지속적인 발견에 대한 기사를 작성하고 있습니다. 개요 작성을 도와주세요."

**프로세스**:
1. 개요 구조에 대해 협업
2. 조사 필요 식별
3. 사용자가 소개 작성 시작
4. 후크 검토 및 개선
5. 사용자가 각 섹션 작성
6. 각 섹션 후 피드백 제공
7. 조사 수행 및 인용 추가
8. 완전한 초안의 최종 검토
9. 게시를 위한 광택 및 준비

**결과**: Teresa의 목소리로 작성된, 강력한 구조와 흐름을 가진 잘 조사되고 적절하게 인용된 기사.

### 예시 2: 조사 중심 기사

**사용자**: "제품 관리에 대한 AI의 영향에 대해 작성하고 있습니다. 현재 데이터와 예시를 찾는 데 도움을 주세요."

**출력**:
```markdown
## 수집된 조사

### 최근 데이터
- Gartner: 2025년까지 PM의 80%가 AI 도구 사용 [1]
- 설문조사: 45%가 더 빠른 기능 출시 보고 [2]
- 사례 연구: Airbnb의 AI 지원 우선순위 지정 [3]

### 전문가 인용
- "AI는 PM 판단을 증폭하지, 대체하지 않습니다" - Marty Cagan
- [인용이 있는 추가 인용]

### 실제 예시
1. **회사 A**: 사용자 조사 종합에 AI 사용
   - 결과: 60% 시간 절약
   - 출처: [인용]

2. **회사 B**: AI 기반 로드맵 분석
   - 결과: 더 나은 이해관계자 정렬
   - 출처: [인용]

모두 적절한 인용과 함께 개요에 추가됨.
```

### 예시 3: 후크 개선

**사용자의 원래 후크**:
> "AI 때문에 제품 관리가 변화하고 있습니다. 이 기사에서는 AI가 제품 관리자에게 미치는 영향의 몇 가지 방법을 논의하겠습니다."

**개선된 옵션**:

**옵션 1 (데이터 중심)**:
> "지난달 AI에게 500개의 고객 인터뷰를 분석하도록 요청했습니다. 3주가 아닌 30분이 걸렸습니다. 제품 관리는 결코 같지 않을 것입니다."

**옵션 2 (질문)**:
> "아침 커피를 마시기 전에 모든 고객과 대화하고, 모든 리뷰를 읽고, 모든 지원 티켓을 분석할 수 있다면 어떨까요?"

**옵션 3 (스토리)**:
> "Sarah는 잘못된 기능을 구축하는 데 2주를 보냈습니다. 사용자를 이해하지 못해서가 아니라, 패턴을 발견하기 위해 수백 개의 인터뷰를 충분히 빠르게 처리할 수 없었기 때문입니다."

### 예시 4: 섹션 피드백

**사용자**: "방금 '일반적인 실수' 섹션을 완료했습니다. 생각은?"

**응답**:
```markdown
# 피드백: 일반적인 실수 섹션

## 잘 작동하는 것 ✓
- 강력한 예시 (Slack 알림 스토리)
- 명확한 구조 (3가지 실수, 깔끔한 레이아웃)
- 각 실수에 대한 실용적인 조언

## 제안

### 더 구체적으로 만들기
두 번째 포인트는 "나쁜 우선순위 지정"이라고 하지만 더 강할 수 있습니다:

현재:
> "많은 팀이 결과 대신 기능에 집중하여 우선순위를 잘못 지정합니다."

제안:
> "팀이 분기에 14개 기능을 출시했지만 주요 지표를 전혀 이동하지 못한 것을 봤습니다. 그들은 진행보다 활동을 우선시했습니다."

### 데이터 추가
세 번째 실수는 증거로부터 이익을 얻을 것입니다:
> "[인용 추가]: 연구에 따르면 정기적인 사용자 접촉이 없는 팀은 사용되지 않는 기능을 만들 가능성이 3배 더 높습니다 [출처 필요]"

### 흐름 개선
재정렬 고려: 실수 3 → 실수 2 → 실수 1
이것은 작은 것에서 큰 영향으로 구축됩니다.

다음 섹션 준비 완료!
```

## 작성 워크플로우

### 블로그 게시물 워크플로우
1. 함께 개요 작성
2. 핵심 포인트 조사
3. 소개 작성 → 피드백 받기
4. 본문 섹션 작성 → 각각 피드백
5. 결론 작성 → 최종 검토
6. 광택 및 편집

### 뉴스레터 워크플로우
1. 후크 아이디어 논의
2. 빠른 개요 (더 짧은 형식)
3. 한 세션에서 초안 작성
4. 명확성 및 링크 검토
5. 빠른 광택

### 기술 튜토리얼 워크플로우
1. 단계 개요 작성
2. 코드 예시 작성
3. 설명 추가
4. 지침 테스트
5. 문제 해결 섹션 추가
6. 정확성을 위한 최종 검토

### 사고 리더십 워크플로우
1. 독특한 각도 브레인스토밍
2. 기존 관점 조사
3. 논제 개발
4. 강력한 POV로 작성
5. 지원 증거 추가
6. 설득력 있는 결론 작성

## 전문가 팁

1. **VS Code에서 작업**: 장문 작성에는 웹 Claude보다 나음
2. **한 번에 한 섹션씩**: 점진적으로 피드백 받기
3. **조사를 별도로 저장**: research.md 파일 유지
4. **초안 버전 관리**: article-v1.md, article-v2.md 등
5. **소리 내어 읽기**: 피드백을 사용하여 어색한 문장 식별
6. **마감일 설정**: "오늘 초안을 완료하고 싶습니다"
7. **휴식 취하기**: 작성, 피드백 받기, 일시 중지, 수정

## 파일 조직

작성 프로젝트에 권장되는 구조:

```
~/writing/article-name/
├── outline.md          # 개요
├── research.md         # 모든 조사 및 인용
├── draft-v1.md         # 첫 번째 초안
├── draft-v2.md         # 수정된 초안
├── final.md            # 게시 준비 완료
├── feedback.md         # 수집된 피드백
└── sources/            # 참고 자료
    ├── study1.pdf
    └── article2.md
```

## 모범 사례

### 조사용
- 인용하기 전에 출처 확인
- 가능하면 최근 데이터 사용
- 다양한 관점 균형
- 원본 출처에 링크

### 피드백용
- 원하는 것에 대해 구체적으로: "이것이 너무 기술적인가요?"
- 우려 사항 공유: "이 섹션이 지루할까 걱정됩니다"
- 질문하기: "이것이 논리적으로 흐르나요?"
- 대안 요청: "이것을 설명하는 다른 방법은 무엇인가요?"

### 목소리용
- 작성 예시 공유
- 톤 선호도 지정
- 좋은 일치 지적: "그것이 나처럼 들립니다!"
- 불일치 표시: "내 스타일에 너무 공식적입니다"

## 관련 사용 사례

- 기사에서 소셜 미디어 게시물 생성
- 다양한 대상을 위한 콘텐츠 조정
- 이메일 뉴스레터 작성
- 기술 문서 초안 작성
- 프레젠테이션 콘텐츠 생성
- 사례 연구 작성
- 강좌 개요 개발
